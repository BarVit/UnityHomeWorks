# ТЗ-02. Разбор `Game.cs`

[← План развития](Roadmap.md) · раздел 9

**Вид работы:** рефакторинг
**Зависит от:** отчёт код-ревью
**Блокирует:** ТЗ-03, ТЗ-05, ТЗ-06

## Цель

Разнести `Game.cs` по ответственностям так, чтобы уровень стал одним шагом внутри локации,
а не единственной сущностью в игре. Поведение при этом не меняется ни в чём.

## Текущее состояние

`Assets/Scripts/Game.cs`, 214 строк — самый крупный файл проекта. Держит одновременно:

1. счётчик уровня и формулу размера волны (`_level`, `GetWaveSize`);
2. победу и поражение (`WinLevel`, `LoseLevel`, `_isLevelOver`);
3. паузу — `Time.timeScale`, `AudioListener.pause`, блокировку ввода;
4. маршрутизацию пяти экранов, включая флаг `_isSettingsFromPause`;
5. отложенный показ экрана поражения корутиной `ShowGameOver`.

Одиннадцать `[SerializeField]`-ссылок и двенадцать подписок в `OnEnable`.

## Разделение

| Класс | Ответственность |
|---|---|
| `LevelRunner` | Один уровень: старт волны и астероидов, победа, поражение, остановка |
| `ScreenRouter` | Экраны и переходы между ними, включая «откуда пришли в настройки» |
| `PauseController` | `Time.timeScale`, `AudioListener.pause`, блокировка ввода |
| `RunState` | Состояние забега: номер уровня, флаги. Обычный класс, не `MonoBehaviour` |
| `Game` | Тонкая точка сборки: связывает перечисленное и больше ничего |

`LocationRunner` здесь **не** появляется — он в ТЗ-03. Это ТЗ только освобождает под него место.

## Не входит

- Любые изменения игрового поведения.
- Последовательность уровней и логика локации.
- Вынос параметров уровня в таблицу — это ТЗ-03.

## Критерий готовности

1. Игра ведёт себя ровно как до правки: старт, победа, варп, поражение, рестарт, пауза,
   настройки из меню и из паузы — всё как было.
2. Ни один из новых классов не превышает ~80 строк.
3. Для каждого формулируется **одна** причина для изменения.
4. `Game.cs` не содержит игровой логики.
5. Замечания ревью по SRP к `Game.cs` закрыты.

## Известные ловушки

- **Парность подписок.** В `OnEnable` двенадцать `+=`; при разносе по классам каждый должен
  сохранить свой `-=`. Потерянная отписка здесь не даст видимого симптома сразу.
- **Пауза — это три действия, а не одно.** `Time.timeScale`, `AudioListener.pause`
  и `LockInput` должны переехать вместе, иначе получится наполовину поставленная на паузу игра.
  Музыка при этом обязана продолжать играть.
- **`_isSettingsFromPause` — состояние маршрутизатора**, а не игры. Уезжает в `ScreenRouter`.
- **`ShowGameOver` ждёт `_playerShip.DeathDuration`** и хранит ссылку на корутину, чтобы
  остановить её при рестарте. Эту пару «запустил — умею остановить» нельзя разорвать.
- Рефакторинг проверяется только игрой: автотестов в проекте нет.
