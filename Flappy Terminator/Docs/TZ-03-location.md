# ТЗ-03. Локация и забег

[← План развития](Roadmap.md) · раздел 3

**Вид работы:** игровая логика
**Зависит от:** ТЗ-01, ТЗ-02
**Блокирует:** ТЗ-04, ТЗ-11

## Цель

Уровень перестаёт быть единицей игры. Единицей становится локация — 3 и более уровней подряд
без сохранений, с общим забегом и общим итогом.

## Что делаем

### `LocationRunner`

Ведёт последовательность уровней внутри локации:

- запускает уровни по очереди, между ними — варп-прыжок;
- по завершении последнего — локация пройдена;
- при смерти игрока — забег сброшен, локация начинается с первого уровня;
- при выходе из игры посреди локации — то же самое, локация не засчитана.

### Награда

**Копится за убийства, начисляется за пройденный уровень.** Убитые враги наполняют счётчик
текущего уровня; счётчик переходит игроку в момент варп-прыжка. Погиб — накопленное за этот
уровень пропало, заработанное на предыдущих осталось.

Плоская ставка за уровень здесь не годится: она сделала бы выгодной тактику «никого не трогать,
аккуратно долететь».

Само начисление в кошелёк — ТЗ-04. Здесь только накопление и момент фиксации.

### `RunState`

Живёт от входа в локацию до выхода, не сохраняется: номер текущего уровня, накопленная награда
за текущий уровень, зафиксированная награда за локацию.

## Данные

`locations.tsv`:

| Столбец | Смысл |
|---|---|
| `id` | ключ локации |
| `system` | к какой звёздной системе относится |
| `order` | порядковый номер внутри системы |
| `levels` | сколько уровней |
| `border_theme` | ссылка на тему границ |
| `flight_mode` | режим полёта (в демо всегда текущий) |
| `waves` | ссылки на шаблоны волн по уровням |

Параметры `_firstWaveSize` и `_waveSizeGrowth` из `Game.cs` уезжают сюда, метод `GetWaveSize`
исчезает.

## Не входит

- Карта и выбор локации — ТЗ-11. Пока локация задаётся полем в инспекторе.
- Начисление в кошелёк и сохранение — ТЗ-04.
- Боссы на последнем уровне — ТЗ-07.
- Реликты: в демо их нет.

## Критерий готовности

1. Три уровня подряд с варпом между ними → локация завершена.
2. Смерть на третьем уровне → возврат на первый, награда за первые два сохранена.
3. Выход из игры посреди локации и повторный запуск → локация не засчитана, награда
   за пройденные уровни на месте.
4. Награда за уровень зависит от числа убитых, а не постоянна.
5. Число уровней в локации читается из таблицы, а не из поля компонента.

## Известные ловушки

- **`WarpJump.Finished` сейчас ведёт прямо в `StartNextLevel`.** Теперь у него два исхода:
  следующий уровень локации или завершение локации. Это разные ветки, не одна с условием внутри.
- **`EnemySpawner.StartWave` вызывает `ReleaseAll` у пяти пулов** и защищается флагом
  `_isRestarting`, потому что `ReleaseAll` поднимает `Retired` и без флага победа объявлялась
  на рестарте. При добавлении уровней внутри локации этот путь исполняется чаще — проверить,
  что флаг по-прежнему закрывает все случаи.
- **Улетевший за экран враг засчитывается в волну, но не в очки.** Награда должна считать
  убитых, а условие завершения уровня — выбывших. Это два разных счётчика, их легко слить.
- Смерть и выход из игры дают одинаковый исход, но приходят по разным путям: событие `Died`
  и закрытие приложения. Второй путь сейчас не обрабатывается вообще.
