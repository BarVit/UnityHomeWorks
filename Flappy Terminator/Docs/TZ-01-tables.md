# ТЗ-01. Конвейер таблиц

[← План развития](Roadmap.md) · раздел 5

**Вид работы:** инструментарий редактора
**Зависит от:** отчёт код-ревью
**Блокирует:** все остальные ТЗ

## Цель

Числа и содержимое игры правятся в обычном табличном редакторе, попадают в игру без ручных
действий, а ошибка в таблице обнаруживается до запуска, а не в рантайме.

## Раскладка

```
Assets/Data/Tables/*.tsv          источник истины, правится руками, лежит в git текстом
Assets/Data/Generated/*.asset     ScriptableObject, создаются импортёром, руками не трогаются
Assets/Editor/TableImport/        парсер и валидация
```

## Формат

- **TSV**, разделитель — табуляция. Не CSV: в русской локали Excel и Numbers разделяют столбцы
  точкой с запятой, а дробную часть запятой, и CSV ломается на первом же `1,5`.
- Первая строка — имена столбцов.
- Первый столбец всегда `id` — устойчивый строковый ключ (`weapon_laser`, `enemy_fighter`).
- Ссылки между таблицами — по `id`.
- Ссылки на ассеты — по имени файла; импортёр превращает их в настоящие ссылки
  через `AssetDatabase`.

Поддерживаемые типы столбцов: `int`, `float`, `string`, `bool`, перечисление, ссылка на `id`
другой таблицы, ссылка на ассет.

## Парсер

Отдельный явный парсер на каждую таблицу, без рефлексии. Рефлексия здесь выглядит короче,
но прячет соответствие «столбец → поле» и ломается молча при переименовании.

## Когда срабатывает импорт

| Событие | Действие |
|---|---|
| Файл `.tsv` изменился на диске | `AssetPostprocessor` переимпортирует эту таблицу |
| Нажали Play | `playModeStateChanged` → `ExitingEditMode` → переимпорт изменённых |
| `Tools → Tables → Reimport All` | Полный переимпорт |
| Сборка игры | Ничего: `ScriptableObject` уже в ассетах |

## Проверки

При любой из ошибок — сообщение в консоль **с именем файла и номером строки**, и вход в Play
отменяется (`EditorApplication.isPlaying = false`). Игра не должна стартовать на битых данных.

- дублирующийся `id`;
- ссылка на `id`, которого нет в целевой таблице;
- число вне допустимого диапазона (отрицательная цена, ступень 7);
- не найден префаб или спрайт по имени;
- десятичная запятая вместо точки;
- лишний, отсутствующий или переименованный столбец.

## Первые таблицы

Заводятся только те, что нужны ближайшим ТЗ, остальные по мере надобности:

- `locations.tsv` — для ТЗ-03;
- `progression.tsv` — для ТЗ-04.

Кривая размера волны после код-ревью живёт в `LevelProgression` (`_firstWaveSize`,
`_waveSizeGrowth`); её и заменяет строка локации из `locations.tsv`.

## Не входит

- Чтение таблиц в рантайме из `StreamingAssets` — возможное расширение, но не сейчас.
- Загрузка из Google Sheets.
- Редактор таблиц внутри Unity: смысл ТЗ ровно в том, чтобы править снаружи.

## Критерий готовности

1. Правка числа в `.tsv` + вход в Play → новое значение действует в игре, без ручных шагов.
2. Дубль `id` → ошибка с файлом и номером строки, Play не запускается.
3. Ссылка на несуществующий `id` → то же.
4. Десятичная запятая → понятное сообщение, а не `FormatException`.
5. Собранный билд работает, `.tsv` в него не входят.

## Известные ловушки

- **Кодировка.** Numbers и Excel умеют сохранять UTF-8 с BOM и UTF-16. Парсер должен
  это переживать, а не падать на первом символе.
- **Переводы строк.** CRLF и LF вперемешку, пустая строка в конце файла.
- **Кавычки.** Excel обрамляет кавычками поля, содержащие табуляцию.
- **Рекурсия импорта.** `AssetDatabase.Refresh()` внутри `AssetPostprocessor` вызовет импорт
  повторно.
- В этом проекте уже был случай, когда правки молча терялись и это заметили через десяток
  коммитов. Текстовые таблицы дают читаемый `git diff` — это одна из причин выбранной схемы.
