# Editor Bridge

Инструмент разработки, не часть игры. Держит HTTP-слушателя внутри запущенного
редактора, чтобы состояние проекта можно было читать снаружи, не закрывая Unity.

Слушает только `127.0.0.1:17890`. Наружу не смотрит.

## Маршруты

| Маршрут | Что делает |
|---|---|
| `GET /ping` | версия Unity, имя проекта, активная сцена, играет ли, компилируется ли |
| `GET /status` | то же плюс состояние компиляции и список ошибок и предупреждений |
| `GET /log?count=50&level=error` | последние записи консоли; `level=error` оставляет только ошибки |
| `GET /compile` | просит редактор пересобрать скрипты и сразу возвращает управление |
| `GET /shot?path=&width=960&height=540` | рендерит основную камеру в PNG |
| `GET /clear` | чистит накопленный буфер консоли |

## Устройство

`BridgeServer` держит слушателя на фоновом потоке. Unity API доступен только с
главного потока, поэтому запрос кладётся в очередь, а `EditorApplication.update`
разбирает её и отдаёт ответ обратно.

Доменный релоад случается на каждой перекомпиляции и на входе в Play mode, и он
стирает всё статическое состояние. Поэтому слушатель гасится в
`AssemblyReloadEvents.beforeAssemblyReload` и поднимается заново из статического
конструктора — иначе порт остаётся занятым. Запросы, застигнутые релоадом,
получают честную ошибку `the editor is reloading, retry`.

Результаты компиляции переживают релоад через `SessionState`: буфер консоли — нет,
он живёт до первой перекомпиляции.

## Как убрать перед сдачей

```
rm -rf Packages/com.flappy.bridge
```

Пакет лежит вне `Assets/` и не связан с `Assembly-CSharp`, поэтому код игры
ничего о нём не знает и удаление ни на что не влияет.
