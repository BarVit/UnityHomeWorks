# Editor Bridge

Инструмент разработки, не часть игры. Держит HTTP-слушателя внутри запущенного
редактора, чтобы состояние проекта можно было читать и править снаружи, не
закрывая Unity.

Слушает только `127.0.0.1:17890`. Наружу не смотрит.

## Маршруты

### Состояние

| Маршрут | Что делает |
|---|---|
| `GET /ping` | версия Unity, имя проекта, активная сцена, играет ли, компилируется ли |
| `GET /status` | то же плюс режим входа в Play, состояние компиляции, ошибки и предупреждения |
| `GET /log?count=50&level=error` | последние записи консоли; `level=error` оставляет только ошибки |
| `GET /compile` | просит редактор пересобрать скрипты и сразу возвращает управление |
| `GET /clear` | чистит накопленный буфер консоли |

### Сцена

| Маршрут | Что делает |
|---|---|
| `GET /scene?path=&depth=3` | дерево иерархии: имена, активность, списки компонентов |
| `GET /object?path=Player Ship` | все сериализованные поля всех компонентов объекта |
| `GET /set?path=&component=&property=&value=` | пишет одно поле через `SerializedObject`, отвечает `before` и `after` |

`/set` без `component` умеет `active`, `name`, `tag` и `layer`. Ссылки на объекты
пока не пишутся. Дробные значения принимаются и с точкой, и с запятой.

### Игровой режим

| Маршрут | Что делает |
|---|---|
| `GET /play`, `GET /stop` | вход и выход; переключение не мгновенное, состояние проверяется по `/status` |
| `GET /pause?value=true` | пауза и снятие паузы |
| `GET /step` | один кадр вперёд |

### Кадр

| Маршрут | Что делает |
|---|---|
| `GET /shot?width=960&height=540` | рендер камеры в PNG вместе с интерфейсом |
| `GET /shot?mode=world` | только мир, без интерфейса |
| `GET /shot?mode=view` | `ScreenCapture` игрового окна; требует, чтобы вкладка Game была видима |

Путь задаётся через `path=`; по умолчанию `Temp/bridge/shot.png`. В пути проекта
есть пробел, поэтому при явном `path=` его надо кодировать или писать за пределы
проекта.

## Устройство

`BridgeServer` держит слушателя на фоновом потоке. Unity API доступен только с
главного потока, поэтому запрос кладётся в очередь, а `EditorApplication.update`
разбирает её и отдаёт ответ обратно.

Доменный релоад случается на каждой перекомпиляции и стирает всё статическое
состояние. Поэтому слушатель гасится в `AssemblyReloadEvents.beforeAssemblyReload`
и поднимается заново из статического конструктора — иначе порт остаётся занятым.
Запросы, застигнутые релоадом, получают честную ошибку `the editor is reloading,
retry`. Результаты компиляции переживают релоад через `SessionState`; буфер
консоли — нет.

Интерфейс игры висит на Canvas в режиме Screen Space - Overlay, а такой Canvas
компонуется уже после камеры и в `RenderTexture` не попадает. Поэтому на время
съёмки Canvas временно привязывается к камере и сразу возвращается обратно.
Делается это только в Play mode, где изменения сцены всё равно не сохраняются:
в режиме редактирования такая подмена пометила бы сцену изменённой, а снять эту
пометку нечем.

По той же причине `/set` не трогает флаг изменённости сцены во время игры —
`EditorSceneManager.MarkSceneDirty` в Play mode бросает исключение.

## Как убрать перед сдачей

```
rm -rf Packages/com.flappy.bridge
```

Пакет лежит вне `Assets/` и не связан с `Assembly-CSharp`, поэтому код игры
ничего о нём не знает и удаление ни на что не влияет.
